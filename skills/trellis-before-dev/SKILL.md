# trellis-before-dev

方案获批、准备动手修改业务代码前加载本技能。确认代码规范、需求与步骤，避免偏离方案盲目写码。

## 动手前检查清单

| 检查对象 | 文件位置 | 重点看什么 |
|----------|----------|------------|
| 1. 项目代码规范 | `.trellis/spec/<package>/<layer>/index.md` | 命名、目录结构、错误处理、架构边界与质量门要求 |
| 2. 核心需求与验收 | 当前任务的 `prd.md` | 具体要实现的行为与明确不做的项（Non-goals） |
| 3. 技术设计方案 | 当前任务的 `design.md`（如有） | 接口定义、数据流、对外契约、既定验证命令 |
| 4. 执行步骤清单 | 当前任务的 `task.json.steps` | 本步骤要做什么、验收指标、验证方式（ai / human） |

## 遇到冲突的处理规则

- **规范与习惯冲突**：以仓库中已有的项目风格与 spec 为准，不按个人主观偏好随意发挥。
- **方案与代码现状冲突**：如果在动手时发现代码现状与 design/prd 严重不符，**立即停下向用户说明**，更新方案确认后再改，不擅自胡乱兼容。

## 硬性卡点

1. **先看清单后写码**：严禁没看验收指标和设计就直接凭感觉改代码。
2. **单步推进**：按照 `task.json.steps` 逐步执行，做完一步更新一步状态。
