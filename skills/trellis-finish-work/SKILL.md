# trellis-finish-work

当代码已写完、测试全部通过、准备交付收工时使用本技能。

## 收尾四步走

| 步骤 | 操作目标 | 具体动作 / 工具 | 重点注意事项 |
|------|----------|-----------------|--------------|
| 1. 提交业务代码 | git commit | 提交本次修改的业务代码和测试文件 | **先提业务代码**，别和后面的工作流簿记混在一个 commit |
| 2. 标记任务完成 | 标记完成 | 调 `trellis_task_update({ status: "completed" })` | 工具会检查 git 是否干净；若有无关未提交文件，可传 `modified_files` 参数放行 |
| 3. 归档任务目录 | 归档持久化 | **征求用户同意后**，调 `trellis_task_archive({ slug: "..." })` | 严禁手动剪切或直接删除目录；工具会自动移动到 `archive/<yyyy-mm>/` 并解绑会话 |
| 4. 记录研发月报 | 追加日志 | 在 `.trellis/journal/<yyyy-mm>.md` 追加本次交付的一句话摘要与改动点 | 保持简短直观，说明解决的问题 |

## 汇报说明

收工时向用户说明：
- 改动了哪些关键文件、通过了哪些测试；
- 对应的 git commit 说明；
- 任务已完成并归档。

## 硬性卡点

1. **业务代码未提交前，禁止归档任务**。
2. **严禁擅自执行 `git push`**（除非用户明确要求 push）。
3. **严禁执行 `git commit --amend` 篡改历史**。
4. **若用户选择自己手动 commit，尊重用户**，确认后直接跳到收尾汇报，不要强行代劳。
