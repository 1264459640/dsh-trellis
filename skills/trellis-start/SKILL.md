# trellis-start

当当前会话无活跃任务（`no_task`）时，根据用户需求分类，并在**获得明确同意后**建任务。

## 诉求分类与动作

| 场景 | 典型诉求 | 处理动作 |
|------|----------|----------|
| 普通问答 / 查代码 | "这函数在哪调用的"、"解释下这段逻辑" | 直接回答，**不碰 Trellis，不建任务** |
| 一次性免任务快修 | "改个注释"、"免任务直接改" | 征得同意后调 `trellis_task_skip`，直接修改 |
| 新功能 / 特性改造 | "开发用户登录功能"、"接入微信支付" | 询问用户是否创建 `feat` 任务并进入规划 |
| Bug 修复 | "保存报错 500"、"列表加载不出来" | 询问用户是否创建 `issue` 任务并进入排查 |
| 代码重构 | "拆分这个 2000 行文件"、"提取通用模块" | 询问用户是否创建 `refactor` 任务并进入设计 |

## 建任务

建任务**必须使用内置工具 `trellis_task_create`**（工具会自动播种模板、绑定会话并校验 slug）：

```json
trellis_task_create({
  "workType": "feat | issue | refactor",
  "title": "任务标题",
  "name": "简短英文名",
  "mode": "standard | quick"
})
```

- slug 自动生成为 `<work-type>-<mm-dd>-<短名>`（如 `feat-10-21-auth`）。
- 严禁手动建目录或手写 `.trellis/.runtime/sessions/` 文件。

## 硬性卡点

1. **未经用户同意严禁擅自建任务**。
2. **建任务（planning）≠ 批准写代码（impl）**：建完任务只代表进入规划期，方案未确认前禁止修改业务代码。
3. **已有任务不重复建**：若状态已有活跃任务，加载 `trellis-continue` 继续处理。
