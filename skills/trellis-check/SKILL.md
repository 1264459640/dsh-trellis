# trellis-check

在代码编写完成后、提交前运行本技能：跑自动化检查、逐条核对 PRD 验收标准，有问题直接修复。

## 检查矩阵

| 检查维度 | 执行命令 / 检查方式 | 通过标准 | 发现问题处理 |
|----------|---------------------|----------|--------------|
| 1. 类型检查 | 如 `pnpm run type-check` 或 `tsc --noEmit` | 0 errors | 就地修复类型报错 |
| 2. 代码风格 | 如 `pnpm run lint` | 0 errors | 能 auto-fix 的直接修，不能的手动修 |
| 3. 单元/集成测试 | 如 `pnpm test` 或运行对应测试文件 | 全部通过（绿灯） | 修复代码逻辑或更新对应测试 |
| 4. PRD 验收标准 | 对照 `prd.md` 中的验收清单逐项核对 | 全部满足 | 若行为不符继续补齐逻辑 |

## 产物记录

- **feat 轨道**：将检查命令与运行结果记入 `review.md`。
- **issue 轨道**：将测试结果与验证证据记入 `fix-note.md`。
- **refactor 轨道**：将回归测试结果记入 `apply-notes.md`。

## 硬性卡点

1. **发现问题直接就地修**：不要只罗列报错，直接修改代码并重新跑测试，直到全绿。
2. **命令绿灯 ≠ 验收完成**：除了命令无报错，必须确认 `prd.md` 里的业务验收标准全部达成。
3. **检查未全绿严禁交付**：存在未修复的类型报错或测试失败时，禁止标记完成或推进归档。
