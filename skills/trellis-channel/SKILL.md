# trellis-channel

当任务较大、拆分出多个子代理（subagent / teammate）并行或串行干活时使用。

## 派发与协作流程

| 步骤 | 环节 | 具体操作 | 关键要求 |
|------|------|----------|----------|
| 1. 划分工作面 | 任务拆分 | 明确每个子 agent 负责哪些文件/模块 | **写作用域互不重叠**，避免同时修改同一文件造成冲突 |
| 2. 派单指令明确 | 派发任务 | 开头写明当前任务路径与具体要做的事情 | 指明参考哪个产物、允许修改哪些文件、验收标准是什么 |
| 3. 产物式交接 | 完工汇报 | 子 agent 完工后以文件改动与验证结论汇报 | 说明改了哪些文件、跑了什么测试，不写冗长叙事 |
| 4. 主控汇总验收 | 主 agent 收口 | 汇总结果，更新 `task.json.steps` | 统一运行一次集成验证，排查潜在冲突 |

## 派单模板示例

```text
Active task: .trellis/tasks/<slug>
目标：实现 <具体的模块/函数>
参考产物：.trellis/tasks/<slug>/design.md
允许修改的文件范围：<明确的文件或目录路径>
验收标准：编写对应测试并运行通过
```

## 硬性卡点

1. **写作用域隔离**：禁止多个并行子 agent 同时修改同一个文件。
2. **禁止套娃派生**：子 agent 禁止擅自无界限递归派生新的子 agent。
3. **主 agent 终审**：子 agent 完成后，主 agent 必须统一执行 `trellis-check` 跑一遍验证。
