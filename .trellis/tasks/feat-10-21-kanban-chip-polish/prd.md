# PRD：看板与徽标视觉及交互体验升级

## 用户诉求

- 现在的看板和徽标在视觉和交互上都不够好，希望整体提升一个层级。
- 用户明确要求：选中态不要在现有效果上打补丁，要推倒重做（第 2 轮）。
- 选中态的方向已定：实心浮起卡片（第 3 轮）。

## 设计原则

- 推倒重来：选中、激活、hover、焦点四种状态重新定义；旧方案里的蓝色整框、左竖条、右圆点、底边分隔线全部去掉。
- 每种状态只用一种视觉信号表达，不叠加。
- 亮色和暗色共用同一套规则，只换 token。

## 已确认事实（来自 lib/client.js 和测试）

- 涉及三个界面：徽标 TaskChip、迷你看板（KanbanBoard / KanbanTaskItem / KanbanArchive）、展开大看板（KanbanExpandedModal / KanbanLaneCard / 列表视图）。
- 现在"选中"和"激活"在视觉上混在一起；所有样式都是内联写的，没有 hover / focus-visible，也没有过渡动画。
- 有几处颜色写死了，暗色下会失效：ink `#0B0C0D`、brandBar、accentBright、ring。
- host 亮色调色板里，bg-layer-1/2/3 全是 `#ffffff`。所以"浮起"的效果在亮色下必须靠一个微凹的槽加阴影来体现。
- 任务摘要接口已经返回 title，徽标可以直接显示任务标题，后端不用改。
- 现有测试约束：亮色 / 暗色 / fallback 三套主题下对比度都要 ≥ 4.5:1；行内动作不能嵌套；每行恰好一个 ▶ 或 ■；busy 时禁用。

## 状态模型

| 状态 | 表现 |
|---|---|
| 默认 | 透明底，平铺在槽里 |
| hover | 很浅的前景色混合底，同时露出行内动作 |
| 选中 | 浮起卡片：raised 底色 + 柔和阴影 + 1px 细环，标题加粗；不用描边，不用竖条 |
| 激活 | 标题前加品牌色状态点（带呼吸光晕）和"当前"标签；和选中互不影响，可以同时出现 |
| 键盘焦点 | 只在 focus-visible 时显示 2px 品牌色焦点环 |

## 范围

- 徽标：状态点、类型、中文阶段名、截断的任务标题、下拉箭头；加载中 / 无任务 / 失败三种状态分别设计；hover、展开、焦点三种交互态。
- 迷你看板：头部分两行（标题行 + 带数量的分段筛选）；列表放进槽里，行项套用新的状态模型并显示步骤进度；弹出动画；支持 ↑/↓/Enter/Esc；骨架加载、失败、空态；底部提示文案与实际能力一致。
- 展开大看板：遮罩调轻并加模糊；弹窗进场动画；泳道卡片、列表行、归档行、筛选都套用同一套状态模型；进度条和完成标记换成 token 色。
- 实现方式：注入一个带作用域的 `<style>`（类名以 `.tw-` 开头），承载伪类、过渡和 keyframes，并尊重 prefers-reduced-motion。

## 验收标准

- `node --test` 全部通过；对比度测试不退化。
- 新增断言：选中行的背景为 raised token，且不带品牌色 border。
- 行内动作约束保持不变：不嵌套、每行恰好一个 ▶ 或 ■、busy 时禁用。
- 人工验收（亮色 + 暗色）：选中、激活、选中 + 激活、hover、焦点五种状态都能一眼区分；每种状态只有一种视觉信号。
- 键盘：Tab 能走到；↑/↓ 切换选中；Enter 激活；Esc 关闭。

## 非目标

- 不改后端接口和数据结构（lib/board.js、lib/index.js、lib/state.js）。
- 不做拖拽改状态。
- 不改详情面板的信息结构，只统一样式。
