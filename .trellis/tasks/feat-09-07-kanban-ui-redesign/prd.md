# 任务看板面板 UI 重设计 — PRD（最终版）

## 目标与用户价值

将 dsh-trellis 在 DSH Web GUI 中的任务看板面板（会话头部徽标、紧凑看板浮层、展开大看板）从当前朴素的功能性样式**全面重设计**为**精致现代的浅色层次卡片风**（Apple / Vercel 极简工匠风格）：信息层次清晰、状态语义统一、空态/加载态美观，视觉质感明显升级。**不新增任何交互、不改动任何后端行为**，仅 UI/UX 层面重构，让用户在既有工作流中获得更好的视觉体验。

## 已确认决策（用户拍板）

1. **全面重设计，不新增交互**：视觉与布局可全面重构；所有既有交互行为（只读浏览、选中、类型筛选、归档展开、推进任务、激活/解绑、Esc/外部点击关闭）保持不变。
2. **design 阶段用生图模型产出设计稿**（效果图）作为设计参考与验收基线。已产出 2 份效果图：
   - 效果图 1（桌面展开大看板全景）：`.dsh/generated/dsh-auxiliary-1788768836467-1.png`
   - 效果图 2（紧凑浮层 Popover 小看板）：`.dsh/generated/dsh-auxiliary-1788768918319-1.png`
3. **浅色、精致现代工匠风**（Apple / Vercel 质感）：
   - 纯净白卡片（`#FFFFFF`）+ 极柔和浅灰底层背景（`#F4F5F7` / `#F8F9FA`）。
   - 1px 极细微边框（Hairline borders）取代厚重分割。
   - 高对比纯黑主 CTA 按钮（Vercel 风格）。
   - 柔和语义色微圆点（Todo 灰色、In Progress 极客蓝、Review 暖琥珀、Done 翡翠绿）。
   - 严谨的嵌套圆角层次体系（Window: 20px, Lane: 14px, Card: 10px, Badge: 6px, Pill: 9999px）。
4. **顺序约定**：先产出效果图，再依据效果图撰写设计方案（design.md），经用户审查批准后进入实现。

## 范围

### In Scope
- `TaskChip`（含 blank 英雄位）视觉重设计：更精致的状态圆点/标签/悬停反馈。
- 紧凑看板浮层 `KanbanBoard`：**恢复「规划中 | 进行中」两列泳道**（替代当前单列合并列表）+ 视觉全面重设计。
- 详情面板 `KanbanDetails`：信息架构重排 + 视觉重设计（浮层与大看板共用，保持一致）。
- 归档树 `KanbanArchive`：呈现方式重设计（仍按月折叠、只读）。
- 展开大看板 `KanbanExpandedModal`：工具栏/泳道/卡片视觉重设计（含搜索、筛选、归档列）。
- 任务卡片 `KanbanTaskItem` / `KanbanLaneCard`：统一的卡片层级（标题/元数据/状态徽章/进度）。
- 在 alias 变量约束内建立统一的设计 token：间距刻度、圆角刻度、阴影层级、字体层级、动效时长、状态色语义。

### Out of Scope
- **不新增任何交互**：无拖拽、无状态直接修改、无自动轮询、无持久化布局偏好、无新增路由/字段。
- 不改后端：`/api/board`、`/api/bind`、`/api/task-state`、`tracks` 数据结构不变。
- 不改变 DSH Web shell / 宿主组件；仅使用 `--dsw-alias-*` 变量与内联 style（不引入 CSS 文件、样式库或外部依赖）。
- 不改动设置页 `TrellisSettingsTab`。
- 不改 locale 文案语义（仅样式层调整）。

## 验收标准
- [ ] 会话头部徽标、紧凑浮层、展开大看板整体观感为明显的「精致现代浅色层次卡片风」，与 DSH 宿主主题一致（仅 alias 变量）。
- [ ] 紧凑浮层呈现「规划中 | 进行中」两列泳道；两列任务分类与现状数据逻辑一致（按 phase 划分）。
- [ ] 信息层次清晰：标题 > 元数据/阶段流水线 > 产物 > 操作的视觉权重合理；选中/悬停/激活/阻塞/待验证状态视觉语言统一且可区分。
- [ ] 空态/加载态/失败态（无任务、无产物、加载中、加载失败、archived 只读）可理解且美观。
- [ ] 行为零回归：选中、筛选、归档展开、推进任务、激活/解绑、关闭逻辑与现状一致；中文/英文 locale 文案不变或仅样式层调整。
- [ ] `node --check` 通过；既有 `npm test` 全绿。
- [ ] design 阶段产出的效果图与最终实现一致（效果图为设计基线，实现逐项对齐）。

## 约束与风险
- 宿主约束：不得占用/覆盖 DSH 单占位槽；徽标保持一行高度紧凑；样式仅 alias 变量 + 内联 style（client.js 单文件 bundle）。
- 全面重设计回归风险较高：行为零改动为硬约束，impl 阶段需按现状行为清单逐项回归（见 implement.md）。
- 浮层与大看板共用 `KanbanDetails` 与卡片组件：必须保证两处观感一致（共享 token 与组件化重构）。
- 生图模型效果图仅作设计参考与验收基线；受 alias 变量限制（如复杂渐变、玻璃拟态）的效果需在实现时降级并记录。
- **效果图已就绪（09-07）**：已生成桌面展开与浮层弹窗两张效果图，并完成视觉度量解析，顺利进入 design 阶段。
