# Feature Design：工作台视觉高保真还原

status: approved
execution_lane: standard

## 目标与非目标

以参考图 `.dsh/generated/dsh-auxiliary-1788782790255-1.png` 为展开工作台的视觉基线，改善当前实现中窗口尺度偏小、顶部工具栏压缩、泳道卡片密度和详情栏层级不够接近目标的问题。保持所有数据读取、选择、筛选、搜索、会话任务绑定和发往聊天的既有行为不变。

> 用户已于 09-08 明确批准本方案进入实施；设计审查发现的技术约束已补充如下。

## 方案

### 边界
- 仅修改 `lib/client.js` 内 `TB`、`KANBAN_*_STYLE`、`KanbanLaneCard`、`KanbanDetails` 与 `KanbanExpandedModal` 的渲染样式和必要的纯展示性 DOM 结构。
- `lib/board.js` 与 API 路由保持不变；不调整 board payload、tracks 或任务状态推导。
- 视觉 token 继续使用 DSH alias CSS 变量并保留回退色，局部固定颜色仅用于参考图定义的蓝/绿/墨黑强调色。

### 视觉与布局规格
1. **模态与遮罩**：桌面下模态宽度为 `min(1450px, calc(100vw - 64px))`，高度为 `min(92vh, 960px)`；外壳维持约 20px 圆角、白底和柔和大阴影；遮罩为深炭色半透明。
2. **工具栏**：高度约 72px；左右 24px 内边距。搜索框保持 280px、36px，筛选药丸居中；右侧分段控件和关闭按钮维持 32px 可点击区。宽度不足时允许工具栏换行，不得遮挡控件。
3. **主区桌面断点**：视口可用宽度达到 1180px 时，详情栏宽度保持 `340–360px`，左侧剩余区域三泳道等宽，列间距 `16px`，左侧内边距 `20px`；泳道 `minWidth: 0`，不产生页面横向溢出。
4. **主区窄屏策略**：低于 1180px 时详情栏优先保持 `min-width: 300px` 且仍独立纵向滚动；左侧泳道区域允许横向滚动，三列保持每列至少 `220px`，横向滚动只发生在左侧主区而不推动详情栏或页面外壳。低于 760px 时详情栏收缩到 `min-width: 280px`，泳道列最小 `200px`，工具栏继续换行；验收以页面无横向溢出、左右区不重叠、各区内容可访问为准。
5. **泳道与卡片**：泳道为极浅背景、1px 发丝边框、12px 圆角。卡片白底、轻阴影、12–14px 内边距、10px 垂直间距；标题最多两行，slug 使用等宽弱化文本；进度轨 5–6px。选中卡 1.5px 蓝边、轻蓝辉光、右上蓝色指示点；完成卡 100% 绿条和绿勾。
6. **完成视觉规则**：当 `task.phase === 'completed'` 或归档完成语义成立时，卡片进度条视觉宽度强制为 `100%`，即使真实 `totalSteps` 为 `0`；进度文字仍使用真实 `completedSteps/totalSteps`，不伪造计数，只确保完成态视觉完整。
7. **详情栏**：头部、操作、流水线、产物、步骤以细分割线和 16–20px 间隔分组；可操作任务的主 CTA 为全宽墨黑按钮，归档任务保留只读控件；产物行保留现有打开/引用交互，仅强化图标、文本、按钮对齐。
8. **列表视图**：不改变数据/点击逻辑，继承新的外壳、工具栏与详情栏，并保留紧凑轴线对齐。

### 不可改变的行为清单
- 搜索 title/slug、类型筛选、lanes/list 切换和选中任务只更新现有本地状态。
- 泳道仍按宿主下发的 `phase` 分类，详情流水线仍按 `tracks` 单一事实源渲染。
- `activate/deactivate`、推进到聊天、产物文件 token（含归档路径）、Escape、背景/关闭按钮、加载/失败/空状态逻辑保持原回调和语义。

### 数据流
```text
/api/board 既有任务与 tracks 载荷
  -> TaskChip 已有本地 state（filter/query/viewMode/selected）
  -> KanbanExpandedModal 分组与筛选（不变）
  -> 视觉 token + 展示组件（窗口 / 泳道 / 卡片 / 详情栏）
```

### 契约变更
- 无。所有 HTTP 接口、board 载荷、任务字段、回调和 locale key 保持不变。

### 取舍
- 以弹性布局和左侧局部横向滚动还原参考图，而不采用绝对定位，确保不同 GUI 尺寸和缩放比例下仍可用。
- 参考图中的装饰内容只在已有真实数据可支撑时呈现；不虚构任务、文件或步骤明细。

## 验证计划
1. `node --check lib/client.js`：验证 bundle JS 语法。
2. `npm test`：验证既有自动化测试不回归。
3. 按仓库实际可用的插件构建命令重新生成 client bundle；刷新 `http://127.0.0.1:49610` 后手工检查展开工作台。
4. 人工在至少一个宽屏（约 1440px）和窄屏（约 1024px，必要时 760px）验证：页面无横向溢出/重叠；左侧泳道可横向滚动；详情栏固定、可滚动；工具栏换行可用；空/加载/失败状态可见。
5. 逐项回归搜索、类型筛选、两种视图、选中任务、激活/解绑、归档只读、产物打开、发送到聊天、Escape/关闭。
6. 使用已完成零步骤任务确认进度视觉为满格绿条和完成勾，计数文案仍为真实值。

## 风险与回滚
- 风险：单文件内联样式规模大，调整共享 token 可能影响紧凑浮层和列表视图；实施将限制改动范围并逐项验证。
- 风险：当前工作区包含其他未提交代码，禁止执行会覆盖其内容的重置或大范围格式化。
- 回滚：仅回退本任务对 `lib/client.js` 的独立提交/差异；不触及数据或存储迁移。
