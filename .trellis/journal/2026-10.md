## 2026-10-21 — 小看板行内激活 / 取消激活（feat-10-20-compact-kanban-activate）

- 任务：`feat-10-20-compact-kanban-activate`，用户验收通过（▶ 激活 / ■ 取消激活双向生效、选中行不再吞掉按钮）。
- 需求起点：小看板（popover）任务行原本只能看不能切，用户提出"应该能直接激活任务"；实现后验收反馈"只有激活没有取消激活"，遂把行末状态点改成动作槽。
- 实现：`KanbanTaskItem` 由单个 `<button>` 拆为「外层布局盒（承载边框/底色/分隔线/boxSizing）+ 主选择按钮 + 右槽动作按钮」，右槽规则简化为 `active ? ■(t('deactivate')) : ▶(t('activate'))`；`renderIcon` 新增描边 `play` / `stop` 图元；`KanbanBoard` 透传 `busy` / `onActivate` / `onDeactivate`；不再保留静态 brand 状态点。
- 交互要点：点 ▶ = `stopPropagation → onSelect → onActivate`（先高亮再绑定）；点 ■ = `stopPropagation → onDeactivate()`（不调 onSelect，避免取消绑定把当前查看行切走）；`bind` 失败静默、按钮保留可原地重试。
- 验证：本任务两测试文件 37/37；全量 140/140 全绿；变异测试 9 项均精确变红（删 busy / onActivate / onDeactivate 透传、右槽回退 selected 分支、删图标、给 ■ 加 onSelect、插回静态点等）。
- 审查：设计审查 4 轮（v1 blocking → v4 passed）；代码审查 3 轮（v4 blocking → v6 passed）。遗留 follow-up：`KanbanLaneCard` 收到 `active` 却未使用（泳道卡看不到激活态），另开 issue。
- 规范沉淀：`web-ui` 约定 18 增加"更正记录"——取消行末聚焦蓝灯与弥散光晕表述，改为"每行恒有一个动作按钮（▶/■）、不保留静态状态点"。
- 工作提交：`fc9eda8`；任务已归档至 `.trellis/tasks/archive/2026-10/feat-10-20-compact-kanban-activate`。

## 2026-10-22 — feat-10-22-inject-spec-without-workflow（已归档）

- **任务**：免 workflow.md 前提下的工程规范（Spec）动态索引与阶段感知注入
- **工作类型**：feat（standard）
- **提交**：`46c93bd`（spec 索引注入实现）→ `7ea2eef`（任务置完成）→ `21fcd7e`（归档）
- **归档位置**：`.trellis/tasks/archive/2026-10/feat-10-22-inject-spec-without-workflow`
- **缺口成因**：`workflow.md` 原本同时承担"阶段提示词"与"告知项目存在 `.trellis/spec/`"两件事。插件停止创建该文件后，`FALLBACK_BREADCRUMBS` 只讲流程不提规范，而 `lib/resolve.js` 的 `specDir` 字段**零消费者**——spec 根本没有注入通路，不是时机问题。
- **方案**：
  - `lib/spec.js`（新增）：有界 BFS 扫描 `.trellis/spec`（`maxDirs` 限广度、`maxDepth` 限深度、`fs.contains` 拦越界 symlink、signal 可中断、全路径 fail-open）；`formatSpecIndexInstruction` 渲染带**项目根锚点**的紧凑索引；`appendSpecInstruction` 组装 `trellis:spec-index` 段。
  - `lib/index.js`：`system-prompt/assemble` 追加该段，与 `enforceReadonlyPlanning` **解耦**、由独立开关 `injectSpecIndex` 控制；`resolveSpecIndex` 以 project root 为键做 5s TTL memo，把按请求触发的高频路径稳态成本压到 0 次 fs。
  - `lib/state.js` / `lib/breadcrumb.js`：内置面包屑在 planning/in_progress 点名 spec；步骤规范行为**时序感知**（pending/in_progress 先读、blocked 落点、verifying 核对）；修正 `builtin` 表头误报 "no .trellis/ detected"。
  - 设置面板新增 `injectSpecIndex` 开关（中英 label + BooleanRow + projection），README/README_EN 同步。
- **审查**：主会话派独立子代理 findings-first 审查，初审 `blocking:0 / major:3 / minor:9 / nit:4`；三条 major（白名单假绿灯、相对路径无根锚点、热路径无条件 walk）全部修复并补测试，minor/nit 可执行项全部处理。
- **验证**：`npm test` 199 pass / 0 fail；本仓真实探针解析出 `task-engine` + `web-ui` 两份 index.md、渲染约 300 字符；fs 计数测试证明第二次装配零 fs 调用；`npm pack --dry-run` 确认 `lib/spec.js` 随包发布；用户人工验收通过。
- **沉淀**：`.trellis/spec/trellis-workflow/task-engine/index.md` 新增约定 7（spec 索引注入通道的 6 条硬约束）与 2 条已知坑（"不再注入 ≠ 不再读"、配置项必须同步 client/测试/README）。
