## 2026-09-06 — issue-09-06-prune-system-prompt-tools（已归档）

- **任务**：修复规划期只读保护下 System Prompt 工具文本未同步修剪问题
- **工作类型**：issue
- **提交**：`1ebe077`（fix & tests）→ `c6cb639`（mark completed）→ `285151d`（archive）
- **归档位置**：`.trellis/tasks/archive/2026-09/issue-09-06-prune-system-prompt-tools`
- **摘要**：
  - 现象：Web 端开启 `enforceReadonlyPlanning` 后，UI 调试栏中工具列表虽已过滤，但发送给模型的自然语言 System Prompt 中仍残留 `write`、`edit` 等写工具指南，诱发模型越权调用；另外 `lib/client.js` 中 `closeExpanded` 的 `useCallback` 位于条件 return 之后导致 Hooks 顺序异常。
  - 根因：`system-prompt/assemble` 钩子仅裁剪了 `assembled.tools`，未对各个插件通过 `ctx.systemPrompt.section` 注册的 `tool:<name>` section（如 `tool:write`、`tool:edit`）进行过滤，导致系统提示词文本拼接未同步受控。
  - 修复：
    1. `lib/client.js`：将 `closeExpanded` 移至条件 return 之前，修复 React Hooks 规则违反。
    2. `lib/readonly.js`：导出 `applyReadonlySections`，精准过滤非白名单的 `tool:*` sections。
    3. `lib/index.js`：在 `system-prompt/assemble` 钩子中同步修剪 `sections` 并合并返回。
  - 验证：新增 4 组 `applyReadonlySections` 单测，15 项只读测试与 39 项核心套件全部 100% 通过；已打包为 `.tgz` 并在宿主环境中复核验证成功。
